## 1. 问题诊断（数据）

### 1.1 入口数量

22 个页面，侧栏 16 项加底部 5 个固定项。900px 高的窗口里侧栏要滚动。分组按「多久用一次」划分，不是按「用来做什么」。

### 1.2 两个最臃肿的区域

**知识结构：7 个界面回答同一个问题「这门课有哪些知识、彼此什么关系」。**

| 界面 | 实际内容 | 数据从哪来 | UI 代码量（约） |
| --- | --- | --- | --- |
| 总纲 | 章 → 节 → 知识点；可附样卷 | 资料 + 模型整理 | 1.2k 行 |
| 复习全书 | 总纲每个知识点的讲解，包括阅读、编辑、问答、期末一周 | 总纲 + 模型 | 4.6k 行 |
| 备考补习 | 考点清单（大考点 → 考点；考过 / 补充；对应课件页码） | 课件 + 样卷 + 模型 | 1.7k 行 |
| 知识骨架 | 主线脉络、结构图、AI 归并主题、质量检测、Archify 附图 | **题组的主题** + 模型 | 4.1k 行 |
| 旧「知识图谱」（graph） | 题组 → 主题 → 题目的掌握树，另有「学习路径」页签 | 题库 | 1.1k 行 |
| 首页学习目录 | 题组 → 主题，带掌握条 | 题库 | 2.1k 行（study-map） |
| 资料知识图谱（新） | 概念网络 + 证据 + 问答 | 资料 + 模型 | 尚未完成 |

其中有三处直接重叠：

- 总纲和备考补习**都会读样卷**：总纲页上有「提供了试卷？」，备考补习的输入是课件加样卷，两者产出的都是一棵「章 / 考点」树。
- 旧图谱和首页学习目录展示的是**同一份数据**：题组、主题、掌握度。
- 旧图谱和新功能**都叫「知识图谱」**。

**学习流：一个可选功能做成了一整套平台**（UI 约 1.3k 行，后端约 1.4k 行）。

- 同一件事「开始学一个主题」，现在有 4 种开法：首页「课程跟学」、学习流「一句话开始」（由 AI 挑主题）、首页「先讲后练」、自定义学习流。
- 自定义学习流本身是一个编辑器：最多 5 条流程，每条 1–16 步，由 6 种组件拼成，每步有两个分支，还能「和主对话一起拼」。
- 学习流会在后台**再生成一份知识骨架**，和知识骨架页重复。
- 每一步都能「交给主对话」，并保留 10 个历史版本。
- 「今天做什么」又有另一套：首页今日卡、推荐下一步、下一步侧卡、「今天先做什么」（AI 安排，**首页和待办页各一份**）、「为你定制」、「回到题目」。

### 1.3 UI 层级问题（走查结果）

1. 同一个课程范围下拉框在 19 个组件里各画一份。课程本该是全局设置，现在每个页面都要重新选。
2. 首页平铺了 12 块内容，同一屏里有 3 个「下一步」互相抢焦点。
3. 「每屏一个主按钮」的规则被打破，例如备考补习和待办页都有两个主按钮。
4. 页头不统一：知识图谱页标题偏小、工具条拥挤；任务页是控制台样式；知识骨架页底部嵌了一张推广卡。
5. 总纲、草稿、维护题组等二级页在侧栏里没有归属；面包屑永远只有一级。
6. 查看详情的方式各不相同，有的弹窗，有的开右栏，有的整页跳转。

## 2. 目标结构

```
顶栏：[课程 ▾]  空间 › 视图 › 对象                    [⌘K] [活动中心 ●] [学习库状态]
侧栏：
  今天    唯一的「下一步」；先讲后练的学习会话
  资料    资料库 · 录音与转写 · 生成
  知识    大纲（结构 / 阅读 / 考点）        [概念网络：实验开关，默认关闭]
  练习    题库 · 待巩固 · 考试
  记录    笔记 · 统计 · 待办
  ────
  设置
```

| 指标 | 现在 | 目标 |
| --- | --- | --- |
| 侧栏项 | 16 个页面 + 5 个底部项 + 3 个分组标题 | 5 个空间 + 设置 |
| 用户可达的页面 / 视图 | 22 | 12（其中 3 个是运行页或子视图） |
| 「知识结构」类界面 | 7 | 1（大纲，有 3 种模式）+ 1 个实验视图 |
| 「开始学一个主题」的方式 | 4 | 1（学习会话，可从 3 个地方进入） |
| 首页内容块 | 12 | ≤ 4 |
| 同屏主按钮多于 1 个的视图 | 若干 | 0（由测试守卫） |

## 3. 功能处置清单

处置分 4 种：**保留**（原样留下）、**合并**（并入其他功能）、**迁移**（换个位置）、**下线**（去掉入口、页面和公开动作，数据保留）。

### 3.1 今天

| 现有功能 | 处置 | 去向 / 说明 |
| --- | --- | --- |
| 首页今日卡（接着做 / 接着学 / 继续学习） | 保留 | 成为「今天」唯一的主行动卡。沿用现有的优先级规则（`study-workflows` 文档「首页主卡给什么」那张表） |
| 推荐下一步、下一步侧卡、其他开始方式 | 合并 | 并入主行动卡的决策函数：只输出一个主行动，另加至多 3 条次要链接 |
| 侧栏「回到题目」 | 合并 | 「接着做」本来就是主卡的第一优先级，侧栏这一行去掉；保留 `S` 快捷键 |
| 今天先做什么（DailyPlan） | 合并 + 部分下线 | 保留「每日时长」，作为今日队列的一项属性；**下线 AI 协商安排**（提议 / 接受 / 调整反馈）。待办页里重复的那一份删掉 |
| 侧栏「为你定制」 | 迁移 | 定制题改在「练习 › 待巩固」里出现 |
| 学习模式开关（课堂跟学 / 笔试·面试） | 迁移 | 移到课程设置 |
| 示例横幅、课程准备清单 | 保留 | 仍在「今天」顶部，不变 |

### 3.2 学习流 → 改为「学习会话」

| 现有功能 | 处置 | 去向 / 说明 |
| --- | --- | --- |
| 「先讲后练」的核心步骤：讲解 → 复述 → 练习 → 总结 | 保留 | 改为**固定 4 步**的「学习会话」，不能再编辑步骤 |
| 一句话开始（AI 挑最多 12 个主题） | 下线 | 学什么改由所选对象决定：今天主卡、大纲里的知识点、待巩固的主题。会话入口从此只有这三个 |
| 自定义学习流编辑器（5 条 / 16 步 / 分支 / 6 种组件 / 和主对话一起拼） | 下线 | 已保存的流程数据保留，不再显示 |
| 「知识骨架」步骤、后台自动生成骨架 | 下线 | 结构由大纲提供 |
| 「明确目标」步骤 | 下线 | 目标就是所选的知识点或主题 |
| 讲解步的换例子 / 拆开讲 / 补前置 / 改写和撤销 | 保留 | 这是会话的核心价值 |
| 其他步骤的「交给主对话」和 10 个历史版本 | 下线 | 只在讲解步保留一个「请主对话讲清楚」 |
| 学习流侧栏页（今天想学什么） | 下线 | 会话是一个运行页，不在侧栏里 |
| 学习记录 | 迁移 | 「今天」显示「继续上次的会话」；完整历史放到「记录 › 笔记」的筛选里 |
| 进行中的旧学习 | 兼容 | 能对应到固定 4 步的，继续可用；用自定义流程开始的，只读查看，并提示「用新会话重新开始」 |

预计删掉学习流约 **55%** 的 UI 代码和约 **40%** 的后端动作。要下线的动作包括 `workflow.save`、`workflow.delete`、`workflow.guide`、`workflow.quickstart`、`workflow.rescope`、`workflow.skeleton.generate`，以及会话里与步骤编排有关的部分。实施时会逐个核对引用后再删。

### 3.3 知识空间

| 现有功能 | 处置 | 去向 / 说明 |
| --- | --- | --- |
| 总纲 | 保留，**作为知识空间的唯一结构源** | 「知识 › 大纲 › 结构」：章 → 节 → 知识点，每个节点显示掌握度，提供「练这一节」和「学这个知识点」（开一次学习会话） |
| 复习全书 | 合并 | 「知识 › 大纲 › 阅读」：同一棵大纲的讲解全文。`study-book` 技能和 `book.*` 动作不变 |
| 备考补习（考点清单） | 合并 | 「知识 › 大纲 › 考点」：在大纲节点上标「考过 / 补充」和课件页码。生成入口移到「资料 › 生成 › 大纲」，样卷作为可选输入（总纲本来就支持）。已有考点清单保留，只读显示。**这是最大的一项改动，单独作为一个阶段（S5）** |
| 知识骨架页 | 下线 | 「AI 归并主题」「质量检测」移到「练习 › 题库 › 维护」（它们实际是在维护题组）；主线脉络由大纲替代；结构图和 Archify 附图下线。已保存的骨架保留数据，并可在「设置 › 数据」导出为 Markdown 或 JSON |
| 旧「知识图谱」（掌握树 + 学习路径） | 下线 | 掌握度改在大纲节点和题库列表里显示 |
| 首页学习目录 | 迁移 | 移到「练习 › 题库」 |
| 资料知识图谱（新） | 隐藏 | 页面加实验开关 `knowledgeGraph`（默认关闭），在「设置 › 实验性功能」中打开；后台自动构建默认就是关闭的，不受影响。功能完成后作为「知识 › 概念网络」上线，届时再评估它与大纲的分工 |

预计知识空间删掉约 **5–6k 行**：骨架约 4.1k 行、旧图谱约 1.1k 行、备考补习的独立页面约 1.7k 行。合并备考补习时，大纲还需要新增约 0.5–1k 行。

## 4. UI 层级体系

| 层级 | 位置 | 内容 | 规则 |
| --- | --- | --- | --- |
| **L0 外壳** | 侧栏 + 顶栏 | 空间、课程切换、面包屑、活动中心 | 课程**只**在这里切换。19 处 `PageScope` 改为读取全局课程，单页的临时范围（资料、题组）放进 L2 工具条 |
| **L1 空间页头** | 内容区顶部 | 标题、视图切换（分段控件，≤ 5 项）、**唯一一个主按钮** | 除运行页以外，一律用 `PageHeader` 渲染 |
| **L2 工具条 + 内容** | 页头之下 | 筛选、搜索、视图选项；分节内容 | 工具条只占一行，次要操作收进「更多」；分节用细线加小标题，不用等权卡片；说明性长文默认折叠 |
| **L3 详情层** | 右侧抽屉（窄屏时为底部面板） | 资料原文、题目详情、任务详情、大纲知识点 | 看详情不离开当前视图；同时只开一层；按 Esc 关闭 |

用测试守卫这些规则，沿用 `tests/ui-guardrails` 的 ratchet 做法（存量违规逐步清零，新增违规直接失败）：

- 同一视图里主按钮多于 1 个就失败。
- 新增的 CSS 不允许出现原始色值（沿用 `css-token-guard`）。
- 非运行页没有使用 `PageHeader` 就失败。
- 页面里自己渲染课程下拉框就失败。

## 5. 下线的做法与数据安全

1. **数据**：Store 中各集合、旧版学习记录、骨架、考点清单**全部保留**。Store 本来就会保留它不认识的扩展集合，不需要提升 `LATEST_VERSION`。骨架和自定义学习流提供导出。
2. **对外动作**：被下线的 `skeleton.*`、`workflow.*` 中的编排部分、旧 `graph` 的查询，要从对外动作表和 `library.context` 的说明中一起删掉。否则 DSH 主对话的 agent 仍会调用不存在的功能。`presets/study.patch.yml` 和 `skills/study-book` 也要逐条核对（复习全书保留，`study-book` 不受影响）。
3. **旧链接**：旧页面 ID 一律重定向，例如 `skeleton`、`graph` → 知识 › 大纲，`workflows` → 今天，`examprep` → 知识 › 大纲 › 考点，`tasks` → 打开活动中心。导览锚点、侧栏排序的 localStorage 和 `S` 快捷键同步迁移。
4. **说明文档**：在 CHANGELOG 和 `docs/` 里写「功能变化与去向」对照表；把已下线功能的文档改为一句「已下线，数据在设置 › 数据中导出」。
