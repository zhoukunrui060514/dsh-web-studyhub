# 资料一键补题与信箱讲解阅读

用户要求资料页增加一键为未覆盖部分出题、侧边栏增加信箱、模型讲解从信箱打开后独立阅读。沿用用户此前授权：当前会话连续实施，仅重大选择提问；本次交互已明确，常规实现由开发者裁定。

## 行为

- 资料页按钮为“一键补齐未覆盖”。范围取当前资料页课程筛选，归档视图不提供入口。未覆盖沿用现有 coverage 的资料小节规则，已发布题和草稿题均计入；正在进行的部分跳过。
- 单次点击按文档提交既有生成 Jobs，继续现有补齐轮次。已有题组的文档产生下一部分草稿，无已发布题组的文档产生独立草稿。沿用检查发布流程，避免自动改写既有题组。显示已启动、已跳过和失败结果，跳转任务可查看进度和取消。重复点击不重复派发同一文档的活动任务。
- 信箱为侧边栏常驻入口，有未读角标；沿用既有 inbox 列表、已读、通知分类，保持五个学习空间。顶栏原信箱入口移至侧栏，信箱成为独立页面。
- followup / improve / rewrite 讲解类消息打开为独立知识点阅读，不创建或切换 review run。显示知识点、原问题、完整讲解、引用与返回信箱；有需要时用户再主动查看原题。
- 追问正文从题目 followups 解析；新通知保留 followupId，旧通知按问题和通知时间兼容解析，既有 staleFrom 也计入历史标识。改题讲解的新通知保留不可变内容快照（题库仍是唯一可编辑正文），避免有限 revision 被回退/淘汰后历史信件改变；旧改题通知仅在可确定保留版本时解析，否则明确显示完整讲解未保留。其他 PDF、笔记、变式等通知保留现有目的地。

## 复用与实现裁定

采用既有覆盖分析与生成器的文档补题分支，补齐无已发布题组的支持；批量入口只做调度，不另建出题或覆盖率模块。信箱阅读使用只读投影，复用 Markdown / 图片 / 资料引用，避免复制一套知识库。拒绝前端循环盲目整份再出题，因为会重复已覆盖内容；拒绝把讲解复制为新卡片，因为会改变题库和学习记录。

预览升级只更新隔离示例 DSH 的插件，继续使用刚复制的体验库。真实 DSH 与真实学习库不写入。现有其他仓库改动保留。验证覆盖双击/并发、部分覆盖、零题资料、旧通知、无 review 副作用、跨库晚响应和原生 DSH 入口。
