# B1：课程内容融合

> 执行方式：当前会话逐项实施，结束后独立审查。用户已批准后端闭环；普通实现选择记入 ledger，不重复请求确认。

**依据：** [后端闭环设计](../specs/2026-10-21-backend-learning-loop-design.md)，B1。

**目标：** 大纲、阅读、旧考点使用同一课程和大纲节点引用。保留现有 sources 表示和所有旧接口；前端暂停。

## 全局约束

- 在 redesign/five-spaces 工作树开发，保留 S1 改动和已暂存删除。
- 不操作真实 DSH 或学习库，不使用模型生成测试数据。
- curriculum 无新增集合，通过 materials 事务写 sources；读端口声明 materials/system/courses/bank/study。
- 新 API 必须显式提供单课程 scope（稳定 courseId 或 unassigned）；all 拒绝。
- outlineRevision 是当前 outline id 和结构内容的摘要。prepare/apply 在事务内校验，旧接口保持原有语义。
- 考点标注挂在目标 outline 的 curriculumExamPoints 元数据，不改旧清单、不生成题目。

## Task 1：共享全书操作和课程门面

**接口：** curriculum.get({scope, view:'structure'|'reading'|'exam', nodeId?, limit?, cursor?, offset?})，默认 50，上限 200；同一个 outlineRevision 和节点 ID。reading 使用 write:false。curriculum.prepare({scope, expectedRevision}) 显式同步。

1. 添加临时库集成测试：读取不写库、prepare 与旧 open 同结果、过期 revision 拒绝、all 拒绝、节点过滤。
2. 执行 RED；提取 library 中已有 course.outline/course.book/book 处理器到根级共享工厂，旧路由委托。
3. 新增 curriculum context，声明读写权限、schema，注册默认运行时。prepare 复用全书队列和历史逻辑，在写事务中核对 revision。
4. 执行新测试和原全书测试，预期全绿。

## Task 2：旧考点预览和确认

**接口：** curriculum.examPoints.preview({scope,listId,nodeId?,limit?,offset?}) 返回 outlineRevision/listRevision、分页 points、完整 totals。每条为 mapped/ambiguous/unplaced。apply({scope,listId,expectedRevision,listRevision,requestId,mappings:[{pointId,nodeId|null}]}) 返回同一预览。

1. 添加 RED：来源片段唯一归属自动映射、多候选和无证据保留、标题不自动确认、人工确认持久化、重复 requestId 无重复标注、过期 revision/不同课程/非法节点拒绝。
2. 使用既有 documentIndex/leafSegments 计算锚点覆盖，证据必须仍与原文位置及 quote 一致。无位置或失效证据不自动确认。多个证据需一致唯一归属。
3. 确认按 listId 存一份标注（附 listRevision/outlineRevision），请求记录放在同一标注内。重建 outline 后旧标注仍留原 outline，不静默迁移。
4. 原文/清单变更后预览标注过期；人工映射只表示归属，不改变证据有效性。事务内重算并验证引用，原清单不变。

## Task 3：验证、审查、交付

1. 扩充隔离临时库验收：重开持久化、不同库隔离、旧全书人工文字及未归位保护、运行时能力与最小安装。
2. 运行新增测试、原 outline/book/blueprint 相关测试、架构边界/运行时/插件组合检查和改动文件 lint；记录实际输出。
3. 一名独立审查者审查整个 B1；重要问题补回归并修复。
4. 记录 API 与验收文档，只提交 B1 文件；使用已确认 Git 身份推送 github/redesign/five-spaces，核验远端 SHA。

**完成判据：** 三视图共享结构引用；读不隐式初始化；每条旧考点均可对账；旧接口和人工编辑保护回归通过；审查和 GitHub 交付有证据。B2–B7 仍待后续阶段，不把 B1 描述为完整闭环完成。
