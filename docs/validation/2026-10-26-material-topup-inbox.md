## 独立审查与修复

同一个 fresh-context reviewer 完成本轮初审。审查曾因账户额度中断，用户继续后恢复并完成剩余初审。共 5 项 Important，无 Critical 或 Minor。每项由执行者先复现，再修复并验证，没有第二轮复审。

1. 普通生成首轮未保存时批量补题会重复启动：按活动 generation 的 sourceIds 检查同文档占用。
2. 旧通知遇到同名新问题会读到新答案：旧条目匹配加通知时间上界。
3. coach 追问通知没有 followupId，合并时还可能遗留上一条 ID：补齐生产者身份，无 ID 的旧生产者合并时清除旧 ID。
4. improve/rewrite 历史信件随当前题目变动：新增不可变通知快照，旧数据使用保留 revision，缺失时明确显示。
5. 真实 card.update 会迁移追问 digest，单纯比较 digest 漏掉历史状态：同时读取 staleFrom，使用真实编辑 API 回归。

历史版本测试最初的合成题目缺少必填字段，导致编辑校验提前失败；补齐合法 fixture 后，重新验证修复前投影的真实断言失败，再验证修复后的 8/8 通过。该过程记录在 `output/qa/inbox-version-review-red-valid.log` 和 `inbox-version-review-green.log`。

审查排除项及处理：真实模型质量、耗时和费用沿用现有生成器，本轮未额外调用真实模型；真实 DSH/学习库禁止写入，使用全新私有宿主和体验副本验证；其他 dirty QA 文件与既有测试删除保留；三项先报告问题的修复由执行者测试验证；进程强杀恢复没有另做故障注入，本次不扩大既有恢复承诺。

## 实施裁定

| 裁定 | 原因 | 代价 |
| --- | --- | --- |
| 未覆盖沿用小节规则、按当前资料页范围、结果进入草稿 | 保持覆盖计算和发布流程一致 | 用户需要检查发布后再练习；活动资料本次跳过 |
| 多题组默认选引用最多的题组作为草稿目标 | 实现一键批量，无需逐份选择 | 默认目标可能与个人偏好不同，发布时仍可调整 |
| 改题通知存不可变历史快照 | 现有题目 revision 仅保留 5 条且回退会删除，引用无法保证长期稳定 | 通知增加存储；旧消息丢失版本时无法恢复正文 |
